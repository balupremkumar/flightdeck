# Phase 3: less clutter in the chat (plan of record, 2026-10-04)

Source: [[projects/active/flightdeck/docs/plans/qol-roadmap-2026-10-04|QoL roadmap]] rows 3.1-3.5.
Locked: Review collapse first, a time-boxed Claude fullscreen trial, then the Chat view.
Key fact: the diffs on screen are Claude Code's own TUI inside xterm; Flightdeck draws none of it. TranscriptView is a plain-text scrollback snapshot.
Cadence: gate, merge to main, go straight to Phase 4 (no release).

## Streams

C1 Review drawer (Sonnet frontend; owns src/Review.tsx, src/review.css, diff helpers diffgroups/difflines/splitdiff/worddiff + tests; Rust only for hide-whitespace).
Per-file collapse with chevron, Collapse all / Expand all, auto-collapse files whose diff exceeds a threshold (default 300 changed lines, Settings value), collapse unchanged regions to 3 context lines with "Show N hidden lines" expanders (QL-715), Viewed checkbox that collapses the file and unticks itself when the file's diff hash changes (QL-719), Hide whitespace toggle (git diff -w via the existing diff command, new optional flag, async), "Last turn" scope if a cheap signal exists (otherwise defer and say so). State per worktree in memory, persisted per repo in localStorage.

C2 Fullscreen probe (Sonnet, read-only investigation, 1 hour box): can Claude Code's fullscreen/alternate-screen mode (Ctrl+O transcript toggle, click-to-expand tool results) work inside Flightdeck's xterm without breaking scrollback search, TranscriptView, scrollback restore, command marks and attention regexes? Flightdeck sets only TERM/COLORTERM (src-tauri/src/lib.rs ~143). Output: a short findings note in docs/plans/phase3-fullscreen-probe.md with a go/no-go and, if go, the exact env/flags. No product code unless it is a one-line opt-in setting defaulting off.

C3 Chat view (Sonnet backend + Sonnet frontend, after C1 merges if files overlap):
C3a session handshake (backend): fresh Claude panes are spawned with `--session-id <uuid>` generated by Flightdeck (check the installed claude CLI supports it: `claude --help`), the id stored on PaneModel (session doc persisted), resume/fork launches record the resumed id (usage.rs stage_launch_args ~429). Fallback for panes without an id: newest JSONL in the cwd slug, flagged "unpinned".
C3b incremental reader (backend): `#[tauri::command] async fn session_tail(session_id, cwd, from_offset) -> { records, next_offset }` reading only appended bytes (FileState offsets pattern in usage.rs), spawn_blocking, bounded batch size, records reduced server-side to a compact shape: user prompt text, assistant text blocks, tool_use {name, short input summary, file paths}, tool_result {is_error, short summary, diff stats for Edit/Write/MultiEdit computed from the input old/new strings}, timestamps. Never ship full file contents to the webview by default; a `session_record(session_id, index)` command fetches one full record on expand.
C3c Chat view UI (frontend; new src/ChatView.tsx, src/chat/*.ts; PaneView toggle Terminal/Chat per pane, Claude panes only): turns grouped under each user prompt; assistant prose rendered with the markdown renderer and clickable paths (linkify + resolver); tool calls as one-line chips ("Edited src/a.ts +42 -7", "Ran npm test", "Read 3 files") collapsed by default, consecutive same-kind calls folded ("Ran 4 commands"); diffs over N lines collapsed with expand; Normal/Verbose density; find that opens collapsed items on match; sticky last-prompt header; per-turn "N files changed" summary with click to open the Review drawer at that file. The terminal remains the input surface: typing in Chat view focuses a prompt box that writes to the PTY (same path as Broadcast) or simply switches to Terminal on keypress (pick the safer).
C4 pwsh output folding (frontend, owns command-mark code in Terminal.tsx): fold/unfold a command's output using OSC 133 marks (QL-763), collapsed blocks show the command line and exit status.
